Hermes Agent 完全指南：从入门到实战

引言

一个随你成长的开源 AI 智能体 —— 越用越聪明，一次配置，全平台触达

一、什么是 Hermes Agent？

Hermes Agent 是由 Nous Research 开发的开源自托管 AI 智能体框架，采用 MIT 开源协议，目前 GitHub Star 数已突破 **40,000+**，是继 OpenClaw 之后又一现象级爆火的开源 Agent 项目。

官方对它的定义非常直白：

The agent that grows with you.
一个会随着使用不断成长的 Agent。

与普通的对话式 AI（如 ChatGPT）最大的不同在于：Hermes Agent 部署在你自己的服务器或本地机器上，连接你的消息账号（Telegram、飞书、企业微信等），成为你的持久个人智能体——它会学习你的项目、自动构建技能、跨会话记住一切、随时随地触达你。

不是聊天机器人，不是代码补全工具，而是真正意义上的 AI 数字伙伴。

二、核心特色与能力

🔁 特色一：内置学习闭环（自我进化）

这是 Hermes Agent 与其他框架最本质的区别。每次对话结束后，它会自动执行三件事：

动作 说明
提炼技能 将对话中可复用的操作序列转化为结构化技能，存入技能库
沉淀记忆 将用户偏好、工作习惯、项目背景写入持久记忆数据库
深化用户画像 通过 USER.md 持续积累对用户的认知，交互越多越精准

实际效果：第一次让它帮你部署一个服务，它需要问你很多细节；第十次，它已经知道你用什么技术栈、习惯什么部署方式、服务器在哪里——直接干活，不再问废话。

🌐 特色二：多平台统一消息网关

内置 Gateway 消息网关，支持 14+ 主流通信平台，一次配置，全平台统一响应：

  • 国际平台：Telegram、Discord、Slack、WhatsApp、Signal、Matrix、IRC、Mattermost、Rocket.Chat
  • 国内平台：飞书（Lark）、钉钉（DingTalk）、企业微信（WeCom）
  • 其他渠道：SMS（Twilio）、Email（IMAP/SMTP）

你可以在微信走路时发消息给 Telegram Bot，回到电脑继续对话，上下文完全连贯。

⚙️ 特色三：模型无关，支持 200+ 模型

不绑定任何单一提供商，轻松切换：

云端模型：OpenAI（GPT-4o）、Anthropic（Claude）、Google（Gemini）、DeepSeek、智谱 AI、Kimi、通义千问、MiniMax、Nous Portal……

本地部署：Ollama、vLLM、llama.cpp、SGLang……

切换模型只需修改一行配置，无需改动任何业务逻辑。

🧠 特色四：四层记忆系统

层级 存储内容 生命周期

会话记录 历史对话摘要 长期

用户画像 偏好、习惯、项目背景 长期，持续更新

三、Hermes Agent 与 OpenClaw 对比

背景说明：Hermes Agent 是 OpenClaw 的继任者/升级版（同属 Nous Research 产品），不是两个独立体系。Hermes 继承了 OpenClaw 的核心概念（SOUL.md、MEMORY.md、AGENTS.md、Skills），同时在架构和功能上有重大演进。

核心架构对比

维度 OpenClaw Hermes Agent
多 Agent 架构 单一 Gateway，多个 Subagent（qilin/baize/zhuque 等）在同一进程内协作 Profiles 模式：每个 Profile = 独立 Gateway 进程；另有 Delegation 模式：单一 Agent 内并行委派子代理（最多 3 个并发）
进程模型 1 个 Gateway 进程，包含多个 Subagent 线程 每个 Profile 独立进程；Delegation 子代理在父 Agent 进程内
入口设计 单一管家入口（qilin）统一接收需求分发 单一人格入口，通过 delegate_task 主动委派
子 Agent 隔离性 共享内存，隔离程度较低 Profiles 完全隔离；Delegation 子代理独立上下文

资源占用对比

基于 macOS 实测数据（空闲状态）：

系统 进程数 内存占用（空闲）
OpenClaw（1 Gateway + 6 Subagent） 1 个 ~150-300MB
Hermes（单 Profile，单 Gateway） 1 个 ~35MB
Hermes（N 个 Profile） N 个 ~35MB × N（线性叠加）

结论：

  • 跑少量 Agent 时 Hermes 更轻量
  • OpenClaw 多 Subagent 不增加进程数，但 Hermes 跑多 Profile 会进程数暴增
  • 资源敏感场景：优先选 OpenClaw 或 Hermes 单 Profile + Delegation

功能特性对比

功能 OpenClaw Hermes Agent
多平台消息网关 ✅ Telegram / 飞书 / Discord 等 ✅ Telegram / 飞书 / Discord / Slack / Matrix / Mattermost / WhatsApp 等（更全）
200+ 模型支持 ✅ ✅
自我进化学习闭环 ✅ ✅ 更强（Skills 持续自我改进）
四层记忆系统 ✅ ✅（+ Honcho 深度用户画像 + FTS5 会话搜索）
本地模型（Ollama） ✅ ✅
子 Agent 并发数 不限 最多 3 个（Delegation）
子 Agent 层级深度 多级（螭龙/鸾鸟/鲲鹏） 最多 2 层，禁止递归
定时任务（Cron） ✅ ✅
MCP 工具 ✅ ✅
Skills 系统 ✅ ✅ 更成熟
Web UI ❌ ❌（但有 WebSocket 实时输出）
从 OpenClaw 迁移 — ✅ hermes claw migrate 一键迁移

复杂任务拆解能力对比

OpenClaw 优势场景：

多级流水线，每个 Subagent 专职负责一个环节，适合角色分明、流程固定的复杂协作。

Hermes 优势场景：

适合独立任务并行执行，如”同时调研 A/B/C 三个方向”，但层级深度受限。

选型建议

场景 推荐
需要多角色流水线协作（分析→设计→实现→测试） OpenClaw
需要轻量单助手，随时切换消息平台 Hermes
资源受限（内存小、CPU 弱） Hermes 单 Profile
需要多独立助手隔离运行（每个完全独立配置） Hermes Profiles
子任务天然需要 3 个以上并行 OpenClaw
子任务需要多级树形分层（3+ 层） OpenClaw
已有 OpenClaw 配置，想平滑升级 Hermes（hermes claw migrate）
需要深度用户画像 + 会话全文搜索 Hermes

九、多 Agent 配置（Profiles）

这是 Hermes Agent 最强大的功能之一，也是区别于 OpenClaw 单一实例方案的核心能力。

Profiles（配置文件） 是 Hermes 的隔离环境系统：在同一台机器上运行多个完全独立的 Hermes Agent 实例，每个 Agent 都有自己独立的配置、API 密钥、记忆、会话历史、技能和 Gateway。

典型使用场景

场景 配置方式
编程助手 + 个人助理 创建 coder 和 assistant 两个 Profile
工作账号 + 私人账号 使用不同 API Key 和 Telegram Bot
生产环境 + 测试环境 完全隔离，互不干扰
多客户 Agent 服务 每个客户一个 Profile，独立计费和记忆
